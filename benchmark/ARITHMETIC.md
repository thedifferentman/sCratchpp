# 字节内存：整值运算与逐字节运算

这两份新项目比较的是**相同字节内存上的两种运算实现**，与之前比较紧凑布局和字节布局的项目独立。

| 文件 | 实现 |
| --- | --- |
| `arithmetic-number.sb3` | 读取操作数的全部字节 → 合成为 Scratch 普通数值 → 加/减/乘 → 拆字节写回 |
| `arithmetic-bytewise.sb3` | 读取操作数的全部字节 → 逐字节进位加法、借位减法或竖式乘法 → 写回结果字节 |

仅使用原版 Scratch 积木，所有自定义积木均“不刷新屏幕”。**助手仅生成项目与检查结构、算术公式，没有打开或运行 sb3。**

## 运行方式

1. 在 Scratch 或 TurboWarp 中加载一份 sb3，点击绿旗。
2. 默认 N=4096、每样本遍历 2500 次、5 个样本。每项每样本为 **1024 万次二元运算**。
3. 一轮自动测试 `add32`、`sub32`、`mul32`、`add64`、`sub64`、`mul64`，随后执行不计时的精度边界检查。
4. 完成后，结果列表会显示。右键导出，再用完全相同的参数与播放器设置测试另一份。
5. 每项比较 `median` 行。不要把不同位宽或不同运算混算。

建议主要在 TurboWarp 上运行默认大工作量；原版 Scratch 上可以先同时降低两份的遍历次数。低于 0.1 秒的实测样本会报告 `TIMING_TOO_SHORT`；应同时增加两份项目的遍历次数。

```text
逐字节耗时倍率 = bytewise 中位秒数 / number 中位秒数
逐字节剩余速度 = number 中位秒数 / bytewise 中位秒数
```

## 公平性与计时范围

- 两份内存布局完全相同：一个列表项一个字节，小端序。每条记录连续存放 A、B、R，分别占 4 或 8 字节；N 条记录共占 `N × 3 × 字节宽度` 个项目。
- 两份每次操作都先执行相同的 8 次或 16 次字节读取，保存到相同数量的临时变量，然后分别运算，最后写入 4 或 8 个结果字节。
- A、B 在每个样本中保持不变，R 每遍重新计算并覆盖。每个样本开始前重新初始化整块内存。
- 加、减、乘均定义为模 2³² 或模 2⁶⁴ 的结果。逐字节乘法只计算保留结果所需的低位列，不计算最终会丢弃的高位列。
- 字节运算在编译期展开，没有每字节自定义积木调用，也没有执行期间的位运算。逐字节实现的临时和、进位都是小整数。
- 计时包括读取、转换/字节运算、结果写回和共同循环开销。**这是完整的 load/operate/store 内核对比，不是剥离访存后的纯 ALU 指令延迟。**
- 初始化、完整结果校验、输出、样本排序、精度边界测试均不计时。每项先预热最多 5 遍。
- 时钟使用 `（结束的2000年至今天数 − 开始天数）× 86400`。计时期间隐藏全部列表和热循环变量。

## 为什么计时数据和精度边界分开

直接把整数合成 Scratch 数值会受到 53 位有效精度限制。为了避免把“结果错误但更快”混进同一个可比工作负载，六项计时测试的操作数及必要中间结果都选择在两种实现可精确计算的范围内。

- u32 加减包含溢出/借位后的模 2³² 结果。
- u32 乘法的完整乘积可超过 32 位，但小于 2⁵³，然后保留低 32 位。
- u64 加减使用超过 32 位的操作数；加法结果仍可精确表示，减法保持非负，避免普通数值在补成接近 2⁶⁴ 的结果时失去精度。
- u64 乘法的完整乘积小于 2⁵³。仍执行完整的八字节读取、运算实现和八字节写回。

计时参考结果由生成器使用 Python 精确整数预计算，作为隐藏参考列表嵌入项目。计时后**逐元素比较**，不是仅比较一个可能碰撞的校验和；输出的 `errors` 是不匹配元素数。辅助校验和逐元素取模 2³²，避免累计丢失精度。

最后的 9 个 `EDGE` 样例则使用大整数、进位、借位及超出 53 位的乘积，逐字节检查结果，**没有计时**。其中整值运算版出现 `ok=0` 是被测精度限制，不代表计时区间的安全范围样本也失败。逐字节版应全部通过。这个区别会直接体现在导出结果中。

## 输出格式

计时数据：

```text
strategy,case,sample,iterations,seconds,checksum,expected,errors,ok
```

`sample` 为编号或 `median`。中位数行的错误数和校验和取最后一个样本，`ok` 汇总该项所有计时样本和预热是否通过。

边界数据：

```text
EDGE,strategy,case,name,ok,actual_LE_bytes,expected_LE_bytes
```

字节按低位在前输出，以空格分隔。最终 `DONE` 行分别汇总计时样本校验、样本时长和边界通过数量，不将两种正确性结论混在一起。

## 限制与重建

- 测试只包含无符号整数加、减、乘；不包含整数除法、浮点运算或随机访存，也不代表任意 LLVM 程序的总体倍率。
- N 最大 8192，八字节版本的内存列表最多 196608 项；参考列表为 49152 项，分别在原版 Scratch 的项目数限制内。
- 每样本最多 1 亿次运算，遍历次数最多 100000，样本数为 1～9；舞台显示规范化后的参数。
- 如果要取得更稳定的数值，使用同一播放器、同一设置交替运行两份文件，并保持窗口前台。

重建（生成器复用同目录下的 `generate_benchmarks.py` 积木构建器，不会重建或修改旧的基准）：

```powershell
python -B .\generate_arithmetic_benchmarks.py
```

生成器检查 sb3 的积木引用、变量与列表引用、全部 warp 设置和日期计时积木，并用 Python 精确整数校验字节算法的边界和随机小样例。它不启动 Scratch VM。
