# 画笔控制台

控制台是一个独立的 LLVM 库，依赖三个同样可单独使用的库：

- `../pte`：字体数据、码点查找与纯画笔单字绘制。
- `../triangle`：两个三角形组成矩形，覆盖擦除字符区域。
- `../events`：帽子入队、主执行上下文中的回调分派、8 ms timing refresh。

控制台只维护文本状态并调用上述接口；它不额外建立事件帽子或自己的刷新时钟。

## 链接和使用

Console 是普通 scrate 包，版本为 `0.3.0`。在项目 `sCrpp.toml` 的 `[dependencies]`
中声明 `console = "0.3.0"`，模板会自动解析 Events、PTE 的传递依赖并接入源码、头文件、字库和事件。

仓库内开发可使用 `console = { path = "../include/console", version = "0.3.0" }`，无需网站。
修改本地包源码或字体后运行普通构建以更新 `scrate.lock`；`--locked` 不接受未更新的内容。
这三个包不再自动放入基础 C++ SDK。使用方式见 `docs/SCRATE.md`。

```cpp
#include <console/console.hpp>
#include <events/events.hpp>

int main() {
    scratch::console::init();
    scratch::console::writeln("Hello, 世界！");
    scratch::console::flush();

    // 用户选择何时处理事件与让出执行。若需要程序结束后仍能滚屏，
    // 必须让主执行上下文继续运行；main 返回后不会自动建立后台线程。
    while (true) {
        scratch::console::flush();
    }
}
```

`write` 支持 `std::string`、以 NUL 结束的 `const char*`、以及指针加长度。文本按 UTF-8 解码；一个码点可以拆成几次 `write`，`flush` 不会丢弃尚未完成的序列。非法序列转换为 U+FFFD，再由 PTE 以缺字方框显示。未完成序列在下一次收到不合法的续字节时替换；清屏时丢弃。

## 文本和刷新行为

- 默认 40 列、14 行、20 单位字号、128 行历史；左上角为 `(-230,170)`，文字颜色为 `0x202020`。
- `Options` 可以修改列数、行数、字号、历史容量、起点和 RGB 颜色。列数限制为 2～120，行数 1～80，字号 4～128；总历史格子最多 100,000 个。库不自动把自定义尺寸缩放到舞台。
- 一般字符占一列，中日韩宽字符和常用 emoji 码点占两列。字形在格内横向居中；比格子宽的字形只压缩横向坐标，保持纵向字号。字库缺失的字符以方框显示。不支持复杂文字塑形、组合字符合并、双向文字或完整 Unicode `wcwidth`。
- 支持 LF、CR、8 列制表、退格删除前一个显示字符。满行后遇到下一个可打印字符才换行，满行后紧接 LF 不会产生额外空行。退格不会跨越行首。
- 新内容先进入缓冲区；`flush()` 增量绘制新增字符。覆盖、退格、光标和滚屏通过屏幕缓存识别变化区域，使用两个白色三角形局部擦除后补画；不会调用 pen_clear。
- 滚轮向上查看历史，向下返回末尾。一条滚轮请求移动一行。查看旧内容时，新输出保持当前视口；历史被容量上限淘汰时，视口移到仍存在的最早一行。
- `flush()` 先在当前 LLVM 上下文中分派已排队事件，再绘图；画字之间调用 `events::refresh()`。绘制时帽子仅能入队，回调将在后续 `poll()` 或 `flush()` 执行。不会在字形内部让出，也不会递归进入 `flush()`。

历史格子和待绘位置存储在原生 Scratch 列表中，不占 C++ 堆或字节虚拟内存。单元格保存数字码点；宽字符后半格是内部标记，公开 `cell()` 对该位置返回 0。

## 单角色与画笔层

控制台使用唯一 Program 角色的白底视口。`init()` 隐藏角色；视口内的其他图形可能被局部覆盖，视口之外不再被整体清除。`flush()` 保存并恢复角色位置，在让出执行前也恢复位置，返回时保持抬笔。字体颜色和笔粗由 PTE 设置，库不承诺恢复原有画笔状态或角色可见性。

控制台没有新增角色、克隆或独立图层，也不自动将 `printf`、`std::cout` 接入其中。

滚轮识别采用 Scratch 兼容的“上/下箭头帽子被触发，但对应按键当前未按住”推断。普通按住箭头不会主动滚屏，但快速键盘释放和按键与滚轮同时使用存在不可消除的歧义；见事件库说明。

## 状态接口

`line_count()` 返回当前保留行数；`first_visible_line()` 是相对于最早保留行的视口索引；`cursor_column()` 是当前写入列；`cell(history_line,column)` 返回码点，空格以 U+0020 返回，空单元格/宽字符后半格/越界返回 0。这些接口不触发绘制。

`clear()` 清空文本与历史，下次 `flush()` 才清除画面。`scroll(lines)` 接受正数向历史移动、负数向末尾移动。`days_since_2000()` 只是事件库浮点时钟的便利转发，通用代码建议直接使用 `scratch::events::days_since_2000()`。

## 首版行输入

行输入使用独立事件库的键盘队列；帽子只入队，回显和字符串修改仍然在 `flush()` 所在的 LLVM 执行上下文中完成。

```cpp
const std::string name = scratch::console::read_line("NAME> ");
scratch::console::writeln("HELLO " + name);
scratch::console::flush();
```

`read_line(prompt,max_bytes)` 内部反复刷新并主动让出执行，等待 Enter 后返回不含换行符的 `std::string`。首版输入约定：

- 接受 ASCII 空格、数字、字母和符号。库在 `init()` 中通过 `scratch::is_turbowarp()` 检测实际运行环境，不以编译时目标猜测。
- **TurboWarp：采集时按住 Shift 为大写，否则小写；Backspace 删除，反斜杠 `\` 是普通输入字符。** 解释模式和编译模式行为一致。Caps Lock 不参与判断，快速释放 Shift 早于帽子执行时可能得到小写。
- **原版 Scratch：字母回显和返回值使用大写，反斜杠 `\` 作为删除键，不能输入字面量反斜杠。** 原版不产生 Backspace 按键事件。
- Enter 在两种环境中都提交。控制台直接使用事件采集器写入队列的字符，不在稍后回调时再次判断 Shift 状态。
- 删除可以跨越自动换行，但不能删除提示文字。字母重复按键事件会重复输入。
- 默认上限 1024 字节，实际取请求值、当前历史能保留的输入空间和 4096 三者最小值；达到上限时忽略新增字符，仍可删除或提交。上限为 0 时允许提交空行。此限制保证删除时的起点不会被历史淘汰，也控制 C++ 堆占用。
- 不支持中文输入法、粘贴、光标中间编辑、密码遮罩、EOF 或标准流输入。中文提示和输出仍支持。
- 开始输入和后续输入键会将视口返回末尾；等待期间仍可滚轮查看历史。

需要与自己的主循环组合时使用异步接口：

```cpp
if (scratch::console::begin_input("VALUE> ", 128)) {
    std::string result;
    while (!scratch::console::try_read_line(result)) {
        // 其他主循环工作……
        scratch::console::flush();
    }
}
```

同一时间最多一个输入会话和一条待取结果。`begin_input()` 在输入已活动、已有未取结果、键盘处理器注册失败或当前处于事件回调时返回 `false`，不打印提示。`try_read_line()` 只有在结果已完成时才返回 `true` 并修改参数；取一次即消费结果，因此能区分“尚未完成”和“用户提交了空行”。

`input_active()` 查询是否等待输入。`cancel_input()` 取消活动会话，保留已回显的内容并换行，不生成结果；外部调用 `write`/`writeln` 时也会先执行这个取消策略。`clear()` 和 `init()` 会丢弃活动输入及未取结果。

**不能在事件回调中阻塞读取。** 此时 `read_line()` 直接返回空字符串且不改变输入状态；已有活动输入或未取结果时同样返回空字符串。需要明确判断是否启动成功时使用 `begin_input()`。禁止在回调中重新开始输入，也保证同一批按键中 Enter 之后的剩余按键不会误输入下一次会话。事件回调可设置应用自己的标志，由主循环下一次迭代调用 `begin_input()`。

## 标准流适配（0.2.0）

链接此版本和最新基础 SDK 后，`std::cin/cout/cerr/clog` 自动使用 Console。
SDK 负责标准流及格式化，`stdio.cpp` 提供终端传输，不依赖全局构造函数偶然被保留。
显式状态读取、EOF、取消和重新打开接口见 [iostream 文档](../../docs/IOSTREAM.md)。
原有 Console write/writeln 仍然手动 flush；标准流层遵循自己的刷新规则。


0.2.1：等待输入时显示下划线光标，约每 500 ms 切换。输入/退格重置计时；提交、取消、EOF 后消失。光标不进入 cells 或输入字符串，闪烁与移位通过可见区域重绘实现，由 flush 驱动，不建立后台线程。满行等待换行时光标停在最后一格；滚到历史视图时不显示屏外光标。


## 0.3.0 局部擦除

依赖 triangle 0.1.1 的固定点坐标入口。每个擦除矩形由两个三角形组成，边界内缩半像素，
不主动在擦除与补画之间让出线程；8 ms timing refresh 保留在区域更新之后。
原版 VM 自身的长 warp 时间片规则仍然适用，不把 warp 宣称为任意长度的原子事务。

`painted` 保存上次画出的字符，光标位置另记，不进入正文。双宽字符按完整区域修复；
普通追加只画新增字符。光标灭时只擦除所在格、恢复格内文字，亮时只画下划线。
滚屏/clear 比较可见格子，更新有变化的区域；init/布局变化用白色矩形处理旧视口再建立新视口。
绿色旗重启也能按原生列表保存的布局清理旧图像。整个库不使用 pen_clear。

背景为不透明白色，不能恢复被覆盖的背景图；不要在控制台区域内独立修改画笔层。
字号较大时行距给笔粗预留边界：font_size + 2*ceil(font_size/32) + 2；默认 20 字号仍为 24。
擦除继承三角形算法的最小笔粗和近似边缘特性，极小字号的效果仍受 Scratch 渲染限制。
